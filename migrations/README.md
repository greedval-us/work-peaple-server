# Миграции

Добавляйте SQL-файлы с сортируемым префиксом: `0002_create_departments.sql`.
Каждый файл выполняется в отдельной транзакции; не добавляйте свои `BEGIN`/`COMMIT`.
Применённые миграции записываются в `schema_migrations` с контрольной суммой;
изменять уже применённый SQL нельзя — создавайте новый файл.
Параллельные запуски сериализуются advisory lock PostgreSQL.

На удалённом сервере вне контейнера: `npm run migration:run`.
В Compose миграции запускает сервис `migrate` до старта `api`.
Чтобы повторно запустить миграции после добавления файлов:

```sh
sudo docker compose run --rm --build migrate
sudo docker compose up -d --build api
```

`0001_identity_and_access.sql` создаёт пользователей, роли, права и сессии.
После миграций `scripts/bootstrap.mjs` один раз создаёт `admin/admin` и записывает
маркер `initial_admin_v1` в `bootstrap_state`. Пароль хешируется в Node.js;
повторное развёртывание не восстанавливает начальные учётные данные.
Новые права добавляйте новыми миграциями, назначая их системной роли `admin`.
Таблицы сотрудников и отделов появятся отдельно. Для команд вне транзакций, например
`CREATE INDEX CONCURRENTLY`, потребуется отдельная явная процедура миграции.
